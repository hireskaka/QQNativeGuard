# 证据分级（2026-11-25）

> 用户提出的关键质疑：**「本地搞出来的这些"证据"到底能不能验证？」**
>
> 本文档严格区分「可验证的」与「只能推断的」，避免把推断当结论。

---

## 一、可验证的定义

| 级别 | 含义 | 判定方式 |
|---|---|---|
| **A 级：端到端实测** | 有完整的输入→输出证据链，任何人可复现 | 抓包/解密/文件读取，有原始数据 |
| **B 级：静态实证** | 从二进制/代码直接读出，不依赖运行时 | 反汇编、字符串、dex 解析 |
| **C 级：行为观察** | 看到现象，但机制未证实 | 日志现象归纳 |
| **D 级：推断** | 基于 A/B/C 的合理解释，**未经证实** | 归因、模型、假设 |

**关键原则**：**A/B 级可写「已确认」，C 级只能写「观察到」，D 级必须标注「推断」。**

**正确写法**：

### 修正 2：把 D 级当事实

**原写法**（多处）：

**问题**：
- 「RiskType 1/201」来自**腾讯云产品文档**，不是 QQ 内部文档
- 「本地无解」是基于「服务端判定」的推断，虽然合理但未证实

**正确写法**：
> `w21` 的文案是「身份验证失败」，表现为登录成功后被异步踢下线。
> **推断**（未证实）：这是服务端账号级判定。
> 依据：① 现象符合（客户端上报正常但被拒）② 上游作者也这么说。
> **不能证实的原因**：服务端代码不可见。

**原写法**：

> 要证实需要服务端数据，我们拿不到。

## 六、诚实的能力边界

### 能验证的

```
✅ 客户端发出了什么字节（抓包/解密）
✅ 客户端读到了什么值（hook/文件读）
✅ 客户端在什么时刻做了什么（日志）
✅ 二进制里有什么代码/字符串（静态分析）
```

### 不能验证的

```
❌ 服务端收到了什么（中间可能有网关处理）
❌ 服务端如何判定（代码不可见）
❌ 服务端判定的权重（即使知道有评分，也不知道各项权重）
❌ 我们的修改是否「真的」改善了判定（无法做 A/B 对照，因为服务端状态不可控）
```

### 最根本的限制

**我们只能做「黑盒实验」**：
- 改变输入（客户端行为）
- 观察输出（是否被踢、多快被踢）
- **但无法观测中间变量（服务端状态）**

这意味着：**任何关于「服务端如何判定」的结论都是推断，不管多有说服力。**

## 八、下一步该怎么做

**既然服务端不可观测，那就做「可控的黑盒实验」**：

1. **隔离变量**：一次只改一个因素，其他保持不变
   - 固定设备指纹，只换网络 → 看存活时长变化
   - 固定网络，只换指纹 → 看变化

2. **记录基线**：当前条件下多次重登，看存活时长的**分布**（不是单次值）

3. **避免污染**：如果账号已被标记，换什么都会失败 —— 这时实验无法进行

**但用户只剩一个号，做不了高成本的 A/B 实验。** 这是现实约束。
